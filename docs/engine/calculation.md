# Calculation contract 1.0.0

Implementation scope: MSG-20261101-0499 / WO-ORDER-20261101-ASTRA-ENGINE-001, E08–E12. The functions below have no DOM, clock, network, database, or sales side effects. `src/quote.mjs` is unchanged. Fixtures are synthetic and isolated under `test/fixtures/engine/`; production modules do not import them.

## Entry points and exact values

- `enumerateCombinations(input)` in `src/engine/calculation/combinations.mjs`: see [combinations.md](combinations.md) for the finite, declarative search contract. Scalar axes can represent product, specification, unit, site, quantity, cycle, or date intent. Data and constraints come from the caller; no egg-specific constraints are embedded.
- `calculateQuote({input,catalog,priceBook,rules})` in `src/engine/calculation/quote.mjs`: computes explicitly selected offers for declared quantities. It does not choose a supplier, recommendation, or minimum-price objective.
- `periodQuantity(input)` and `monthlyDayIntent(input)` in `src/engine/calculation/period.mjs`: preserve unresolved period/date policy.
- `exact`, `fromRatio`, arithmetic, `round`, and `toJSON` in `src/engine/calculation/exact.mjs`: bounded exact rational arithmetic.

Decimals must be strings; safe integer Numbers are also accepted. Binary floating-point decimals, scientific notation, comma formatting, whitespace, infinities, and unsafe integers are rejected. Quantities can additionally be `{numerator:"…",denominator:"…"}`. Output rationals have those two decimal-string properties, denominator positive and fraction reduced. BigInt is internal only. Numerator and denominator are each limited to 120 digits after reduction; overflow produces `ARITHMETIC_RANGE`. Rounding scale is explicitly 0–12, with `HALF_UP`, `HALF_EVEN`, `DOWN` (toward zero), `FLOOR`, or `CEIL`.

## Quote input and evidence

`input` requires canonical explicit UTC `asOf` (`YYYY-MM-DDTHH:mm:ss.sssZ`) and 1–1000 `lines`. Each line requires unique `id`, `siteId`, `productId`, `unit`, positive exact `quantity`, and explicitly selected `offerId`. `region` is required when an offer declares region restrictions. Optional `comparisonTotal` is a nonnegative exact amount for the same currency/scope; a missing comparison returns `null`, not zero savings.

`catalog` requires `version` and products with unique `id`, `groupId`, `baseUnit`, and `units`. Each `units` value is the positive factor converting that unit to the base unit; the base unit factor must be one. No catalogue or conversion data is generated by the engine.

`priceBook` requires `version` and unique offers. An offer requires `status:APPROVED`, `id`, `priceRevision`, `approvalId`, `approvedBy`, `approvedAt`, `legalSellerId`, `productId`, `unit`, positive exact `unitPrice`, ISO currency code, and `effectiveFrom`; optional `effectiveTo` is exclusive. Date strings have the same canonical UTC shape as `asOf`. Future approvals and out-of-period prices are unavailable. Optional `regions`, `siteIds`, `minQuantity`, `maxQuantity`, and `quantityStep` constrain each line in offer units. `availableQuantity`, if supplied, is checked against the sum of all lines using that offer. No inventory reservation occurs. Missing stock data does not fabricate supply availability: `fulfillmentStatus` remains `NOT_VERIFIED` even for a valid monetary result. Approval metadata is necessary input, not cryptographic proof or authorization; a trusted source adapter remains required before product integration.

`rules` requires `version` and `rounding:{stage:"TOTAL",scale,mode}`. This contract supports exact line arithmetic with a single final total rounding. An unspecified/other rounding stage is `POLICY_UNRESOLVED`. `costComponents` must explicitly provide `tax`, `shipping`, and `discount`, each `{amount,ruleId}`. No tax rate, free shipping, discount policy, or zero charge is assumed. Missing components return `POLICY_UNRESOLVED` with the known merchandise subtotal and `total:null`. These declared component amounts are aggregate quote amounts; per-line tax rules or allocation of shipping must be implemented in a later approved contract.

The result includes normalized line quantities, conversion factors, approval IDs, exact line amounts, per-site subtotals, currency, exact and rounded totals, explicit difference, engine/contract/rule/data versions, and `evidence.replay` containing the complete input/catalog/price/rule snapshot. `calculateQuote(result.evidence.replay)` reproduces a valid or component-policy-unresolved result. All output is JSON-safe. `VALID` means the declared mathematical calculation passed; it does not approve prices, orders, scheduling, fulfillment, stock reservation, tax treatment, or customer disclosure.

## Period and calendar boundaries

`periodQuantity({perDelivery,weeklyVisits,period})` uses exactly one of these shapes:

| Period | Meaning |
| --- | --- |
| `{kind:"FOUR_WEEKS"}` | Four times explicit integer weekly visits (1–7) |
| `{kind:"THIRTY_DAYS",method:"PRORATED_EXPECTATION"}` | Explicit 30/7 prorated weekly expectation; never a rounded or scheduled actual visit count |
| `{kind:"EXPLICIT_VISITS",visits:"…"}` | Explicit positive integer visits |

Unknown/missing policy or contradictory extra period fields is `POLICY_UNRESOLVED`. With one weekly visit and quantity 30 per delivery, four weeks yields exactly 120; a 30-day prorated expectation yields exactly 900/7. Neither is silently substituted for the other. This preserves TC0481-17 from MSG0499 §8.3. `actualCalendarDates` remains null; calendar/holiday/lead-time policies and PENDING27/28 remain outside this implementation.

`monthlyDayIntent({year,month,day})` accepts integer day 1–31 or literal `last`. Year range is 1–9999. Gregorian leap years are deterministic. February 2026 + numeric 31 preserves 31 and returns `POLICY_UNRESOLVED`; February + `last` preserves `last` and resolves its calendar meaning to 28. Moving or skipping deliveries is never implied. A valid calendar day is not a delivery booking.

## Running and calling

```js
import {calculateQuote} from '../../src/engine/calculation/quote.mjs';
import {catalog,priceBook,rules,twoSites} from '../../test/fixtures/engine/calculation-data.mjs';
const result = calculateQuote({input:twoSites,catalog,priceBook,rules});
console.log(result.normalized.total.decimal); // Synthetic only: 44.50
```

This example import is for tests/developer evaluation, never a production bundle. An executable combined choice → explicit period → two-product/two-site quote path is `test/engine/calculation-integration.test.mjs`.

Run `node --test test/engine/calculation*.test.mjs` from the repository root. Independent expectations include:

| Case | Independently tabulated expected result |
| --- | --- |
| Exact decimal sum 0.1 + 0.2 | 3/10 |
| Synthetic 2 trays × 10.25 | 20.50 |
| Synthetic 3 bags × 2.5 kg/bag × 3.20/kg | 24.00 |
| Combined two-site amount, comparison 50 | 44.50; difference 5.50 |
| Constrained four-week path: 8 trays + 4 bags | 82 + 32 = 114.00 |
| Two exact 0.005 lines, scale 2 | 0.01 (no per-line rounding) |
| 2.5 whole-unit HALF_UP / HALF_EVEN | 3 / 2 |
| Existing legacy integer case | 1,320,000; saving 80,000 |
| Main `data/offers.json` empty | UNAVAILABLE / PRICE_UNAVAILABLE; no numerical quote |

## Legacy differences

| Existing `src/quote.mjs` | New independent core | Classification |
| --- | --- | --- |
| Egg-specific housing/size/tray query | Caller-declared generic products/units/sites | Intentional extension |
| Automatically picks lowest eligible price | Explicit offer ID; search does not recommend | Deferred optimization policy |
| Optional implicit current time | Mandatory explicit canonical UTC time | Deterministic contract |
| Number multiplication | Exact rational arithmetic and explicit rounding | Intentional precision change |
| Approved status/id/revision checks | Also requires explicit approval/seller metadata | Stronger integration requirement |
| Monthly amount only | Line/site merchandise plus declared cost components | Intentional extension |
| No empty-price fallback amount | Same UNAVAILABLE semantics | Compatible |
| Legacy monthly and savings integer fixture | Same independently expected 1,320,000 / 80,000 | Regression covered |

Existing API remains callable and its original tests remain unchanged. This independent candidate does not replace the current UI or existing quote API. Actual latest UX source comparisons and environment acceptance are recorded in the root report separately.
